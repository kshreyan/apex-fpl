## Sequencing logic (why this order, not another)

The spec's own Part LXV phase order is followed because it enforces the dependency graph implied by the gap table above: BPS (XIV) cannot be validated without attacking/defensive/GK models existing first; the optimizer (XXIV) cannot be evaluated meaningfully without a scoring engine (XV) and at least a baseline player-points distribution; decision-focused learning (XXVII) is explicitly a challenger track that requires a working prediction-focused baseline to be compared against. Skipping ahead to build the optimizer or the joint simulator before the scoring engine and a baseline minutes/attacking model exist would violate the spec's own stopping rule ("a sophisticated optimizer cannot rescue poor probabilities") and produce something un-auditable.

## Immediate blockers to flag to the user

1. **No event-level (Opta-grade) data source is confirmed available yet.** Defensive contributions, saves, and BPS all require action-level match data (tackles, blocks, interceptions, recoveries, shot locations) that `bootstrap-static`/`fixtures` do not provide. This must be resolved in Phase 1's data-source registry before Parts XII-XIV can be built for real; until then those modules stay stubbed with documented `E` (missing) status rather than faked.
2. **No odds feed is wired up**, mirroring the World Cup repo's honest gap — the de-vig/consensus *math* transfers, a real feed does not exist yet.
3. ~~No historical FPL archive has been verified for point-in-time correctness.~~ **RESOLVED 2026-08-14** — audited in `docs/vaastav_archive_audit.md`. Verdict: conditionally trustworthy. Per-gameweek match/price/ownership columns are sourced from FPL's own frozen per-gameweek ledger (not re-derived), verified both by reading `collector.py` and empirically (461/572 players show genuinely different prices between GW1 and GW38 of the 2022-23 season). Grade A for seasons through 2024-25 (weekly capture, confirmed via commit history), grade B for 2025-26 onward (reduced 3x/season bulk-update cadence, not independently spot-checked). **Confirmed, maintainer-documented leakage risk: the `xP` column** (sourced from a live `ep_this` scrape, not the ledger) — must never be used unshifted, worse for the reduced-cadence seasons. `cleaned_players.csv`/`players_raw.csv` are season-aggregate, not gameweek-dated. Not yet ingested into the Bronze/Silver pipeline — that's the next step if Phase 4 historical model tournaments are prioritized.
4. **NEW (found 2026-08-14 while building Silver tables): `bootstrap_static`'s per-player cumulative stat fields (`total_points`, `minutes`, `bps`, `goals_scored`, etc.) are non-zero in a confirmed pre-season snapshot** (`event_points=0`, GW1 not yet played). These are almost certainly stale 2025/26 season-end totals still populated by the API ahead of the new season, not 2026/27 in-season observations — but this is NOT independently verified yet. The Silver `player_stats` table stores these fields with an explicit `stat_period_note` flag precisely so no downstream code can silently treat them as current-season truth. Resolve by comparing against a second source once GW1 actually finishes and checking whether these fields reset to zero, or by cross-checking specific players against a verified 2025/26 archive now.
